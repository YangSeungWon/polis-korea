# 신뢰 상태 스펙 (trust states)

숫자 하나를 본 사용자가 **"이거 믿어도 돼?"** 라고 생각하는 순간에 답이 있어야 한다.
이 문서는 그 답을 무엇으로, 어디에, 어떤 말로 낼지 고정한다. 여기서 정해 두면 이후 UI
구현에서 판단이 거의 필요 없다.

기준 회차: 9회 지선(2026-06-03). 아래 수치는 2026-08-04 실측이다.

## 네 축 — 하나의 badge로 뭉치지 않는다

신뢰 상태는 한 종류가 아니다. `확정/잠정` 하나로 묶으면 나중에 다시 뜯어야 한다.

| 축 | 데이터 | 답하는 질문 | 범위 |
|---|---|---|---|
| 확정성 | `_meta.is_final` | 이 숫자가 바뀔 수 있나 | 데이터셋 |
| 진행도·완전성 | `count_pct` · `votes_pending` | 데이터가 얼마나 들어왔나 | 섹션·값 |
| 출처 | `_meta.source` | 어디서 온 숫자인가 | 데이터셋 |
| 가공 여부 | `realm_auto` 등 | 공식 원자료인가 polis가 만든 값인가 | 값 |

**데이터셋 단위 신뢰(확정성·출처)와 값 단위 출처(가공 여부)를 분리한다.** 공약 분야
2,909건이 polis 추정이라고 해서 회차 전체에 '잠정'을 붙이면 안 된다.

## 상태 라벨은 데이터 종류별 적용 범위를 가진다

**`확정/잠정`은 선거 결과 데이터에만 적용한다. 조사·출구조사에는 자동 적용하지 않는다.**

출구조사에 '확정'을 붙이면 사용자는 *"이 결과가 확정됐다"* 로 읽는다. 실제 의미는
"방송사가 발표한 값이 더 안 바뀐다"일 뿐이고, **예측 자체는 확정 결과가 아니다.**

| 데이터 종류 | `data_type` | 확정/잠정 | 대신 쓰는 것 |
|---|---|---|---|
| 선거 결과 | (기본) | ✅ | — |
| 출구조사 | `exit_poll` | ❌ | 출처 · 발표 시각 |
| 여론조사 | (aggregated) | ❌ | 출처(NESDC) · 집계 주체 |
| 공약 | (pledges) | ❌ | 출처 · 모집단(`roster_scope`) |

렌더러는 `data_type`을 보고 판단한다. 출구조사 파일에는 `is_final`을 **넣지 않는다** —
필드가 없으면 잘못 표시할 일도 없다(`build_exit_poll_meta.py`).

화면은 오히려 단순해진다:

```
방송 3사 공동출구조사 · 2026. 6. 3. 18:00 발표
실제 결과와 평균 오차 1.8%p  [polis 계산]
```

## 필드별 처리 — 표시 / 조건부 / 상세

| 필드 | 사용자 상태 | 표시 등급 | 조건 |
|---|---|---|---|
| `_meta.is_final: true` | **확정** | 표시 | 항상 (섹션 제목 아래) |
| `_meta.is_final: false` | **잠정** | 표시 | 항상 |
| `_meta.source` | `NEC OpenAPI` · `NEC 실시간` · `NESDC` | 표시 | 확정성 옆 출처 라인 |
| `count_pct < 100` | **개표 87.4%** | 조건부 | 잠정일 때만. 확정본엔 사실상 없다(아래) |
| `votes_pending: true` | **일부 집계 중** | 조건부 | 그 값 옆에만 |
| `is_uncontested: true` | **무투표** | 조건부 | 결손이 아니라 제도적 부재 — 아래 |
| `realm_auto` (원본 `realm` 없음) | **polis 추정** | 조건부 | 그 값 옆에만 |
| 계산 지표(오차·평균 등) | **polis 계산** | 조건부 | 가공된 숫자 옆에만 |
| `carried_from_live` | — | 상세에만 | 아래 |
| `fetched_at` · `finalized_at` | 갱신 시각 | 상세에만 | 잠정일 때는 표시로 승격 |
| `n_calls` · `n_rows` · `n_roster` | — | 상세에만 | 파이프라인 내부 수치 |
| `roster_scope` | 당선인만 / 등록 후보 전체 | 표시 | 모집단이 다르면 분포의 뜻이 달라진다 |

### 실측이 바꾼 것 세 가지

**1. `count_pct`는 잠정 전용이다.**
9회 지선 확정본에서 `count_pct`를 가진 race는 254건뿐이고 **전부 무투표 race의 100.0**이다.
즉 확정본에 '개표 N%'를 붙일 자리가 없다. 이 표시는 생애주기 1단계(개표일)에만 쓴다.

**2. 무투표를 '데이터 없음'으로 라벨하면 안 된다.**
집계값이 비어 있는 254건(tc4 3 · tc5 109 · tc6 142)은 `is_uncontested`와 **정확히 일치**한다.
투표를 하지 않았으니 선거인수·투표율이 없는 게 맞다. 이걸 결손으로 표시하면 교육감
정당 빈값을 '자료 없음'으로 읽었던 것과 같은 오해가 난다. → 표기는 **무투표**, 회색.

**3. 공약 분야는 값 단위 출처가 실제로 필요하다.**
3,330건 중 NEC 원본 분야는 **5건**, polis 추정이 **2,909건**, 미분류 421건이다.
데이터셋에 '추정' 딱지를 붙이는 게 아니라 추정된 값 옆에만 표시한다.

## 사용자에게 보여줄 상태는 여섯 개

내부 필드가 많다고 다 노출하면 오히려 신뢰가 떨어진다. 사용자는 파이프라인을
디버깅하러 온 게 아니다.

1. **확정** — 공식 최종
2. **잠정** — 아직 바뀔 수 있음
3. **개표 87.4%** — 진행 중
4. **일부 집계 중** — 불완전 (`votes_pending`)
5. **polis 계산** — 원자료에서 계산한 지표
6. **polis 추정** — 원자료에 없어 규칙으로 보완한 값

`무투표`는 신뢰 상태가 아니라 **사실 표기**다. 같은 회색 계열로 쓰되 위 여섯과 성격이
다르다는 걸 문서로 남긴다.

출처(`NEC OpenAPI` · `NEC 실시간` · `NESDC`)는 badge가 아니라 **출처 라인**으로 둔다.

## `carried_from_live` — 기본 화면에서 숨긴다

값이 최종본과 같고 정합성 검증까지 끝났다면 일반 사용자가 항상 알아야 할 정보가 아니다.
`데이터 정보`에만 둔다.

단 **"라이브에서 이관했으나 공식 API와 대조 전"** 이면 사용자-facing 상태가 필요하다.
그 경우 `일부 집계 중`과 같은 등급으로 올린다.

> 2026-08-04 기준 9회 지선에는 이 필드가 없다. 비례(tc8·tc9)를 OpenAPI로 편입하면서
> 이관이 사라졌기 때문이다. 앞으로 API가 못 주는 직이 생기면 다시 나타난다.

## 배치 — 숫자 가까이

페이지 하단 disclaimer로 보내면 효과가 거의 없다.

```
광역단체장 결과
확정 · NEC OpenAPI                     ← 섹션 제목 바로 아래

시도의회 의석
확정 · NEC OpenAPI

기초의원 비례
확정 · NEC OpenAPI · 58개 시군구 일부 집계 중   ← 불완전은 여기서 밝힌다

선거 전 여론조사 추세
NESDC 등록 조사 · polis 집계

출구조사 평균 오차 1.8%p  [polis 계산]        ← 가공 숫자 바로 옆
```

값 단위 표시(`polis 추정`·`무투표`)는 그 값 옆에 작게 붙이고, 자세한 설명은
hover/클릭으로 연다.

## 색 — 정치 색상과 분리한다

polis에서 빨강·파랑은 이미 정당을 뜻한다. 신뢰 상태에 `확정=파랑`·`경고=빨강` 같은
일반 SaaS 팔레트를 쓰면 정치적 의미로 오독된다.

- 신뢰 UI는 **중성 회색 계열 + 텍스트 차이**로 읽히게 한다.
- **잠정 ≠ 오류.** 노란 경고 박스로 만들면 사용자는 '문제 있는 데이터'로 해석한다.
  실제 의미는 정상적인 집계 진행 상태다.
- `polis 계산`·`polis 추정`은 점선 테두리로 원자료와 구분한다(교육감 '정당 없음' 칩과
  같은 어휘 — 단정적으로 보이지 않게).

## 처리한 결함 · 남은 것

**출구조사 `_meta`** — 처음엔 '출처가 없다'고 봤으나 오진이었다. `sources[]`에 이미
`name`·`released_at`·`quote_after`가 있었고 `_legal_note`(KEP 인용 기준)도 있었다.
비어 있던 건 데이터셋 단위 요약뿐이라, 있는 값으로 `_meta`를 만들었다
(`build_exit_poll_meta.py`). **없는 값은 만들지 않았다** — 21대 대선·22대 총선은
`released_at`이 비어 있어 `published_at` 없이 나가고, 화면은 발표 시각을 빼고 출처만 보인다.

**확정 승격이 `source`를 지우던 문제** — 고쳤다(`nec-openapi` 설정 + `finalized_at`).
지우면 '확정'인 건 알아도 '어디서 온 확정인지'가 사라져 출처 라인을 못 만든다.

**남은 것** — 21대 대선·22대 총선 출구조사의 발표 시각. 근거를 찾으면 채운다.

## 대표 fixture — 컴포넌트는 이 여덟 개로 검증한다

컴포넌트를 먼저 만들고 페이지를 뒤지며 예외를 발견하는 대신, 실제로 존재하는 상태를
먼저 골라 둔다. 전부 9회 지선 페이지 한 장에서 나온다.

| # | 상태 | 실제 데이터 | 층 |
|---|---|---|---|
| 1 | 확정 · NEC OpenAPI | `9th-local-2026` `is_final:true` `source:nec-openapi` | dataset |
| 2 | 잠정 · 개표 N% | 생애주기 1단계 (현재 회차엔 없음 — 다음 선거) | dataset |
| 3 | 일부 집계 중 | tc9 비례 `votes_pending` 58개 시군구 | value |
| 4 | 무투표 | tc4 3 · tc5 109 · tc6 142 (`is_uncontested`) | 도메인 사실 |
| 5 | polis 추정 | 공약 분야 `realm_auto` 2,909건 | value |
| 6 | polis 계산 | 출구조사 평균 오차 등 파생 지표 | value |
| 7 | 출구조사 | `data_type:exit_poll` · 발표 18:00 · 확정/잠정 **없음** | dataset |
| 8 | 여론조사 | NESDC 등록 · 모집단 `roster_scope` | dataset |

2번은 현재 회차에 실물이 없다(확정 승격 완료). 다음 선거 개표일에만 나타나므로
컴포넌트 단계에서는 합성 fixture로 확인하고, 실제 검증은 그때 한다.

## 컴포넌트는 두 층이다

하나의 만능 badge가 아니라 개념이 다른 두 층으로 나눈다.

- **Dataset provenance** — 확정/잠정 · 출처 · 갱신·발표 시각 · 모집단. 섹션 제목 아래 한 줄.
- **Field provenance** — polis 계산 · polis 추정 · 자동 분류. 그 값 옆 작은 칩.

`무투표`는 둘 다 아니다. **도메인 사실**이라 별도 어휘로 남긴다 — 신뢰가 낮아서가 아니라
투표가 없었던 것이다.

## 적용 순서

1. **이 스펙 고정** ← 지금
2. 공통 컴포넌트 — `상태 · 출처` 라인과 값 단위 칩
3. 9회 지선에 전면 적용해 밀도·중복 확인
4. 그 페이지를 기준으로 대선·총선·history·tracker로 확장
