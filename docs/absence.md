# 없다 · 모른다 · 0 · 못 받았다

이 저장소가 반복해서 겪은 결함은 사실상 **하나**다. 서로 다른 뜻의 결손이 한
자리에 눌려 담기고, 읽는 쪽이 그중 그럴듯한 하나로 읽는다. 표가 엉뚱한 정당에
붙고, 화면이 없는 사실을 단언하고, 아무도 못 본다.

지금까지 **열여섯 번** 나왔다. 데이터·산출·화면 세 층에 고루 나왔고, 매번 다른
문제처럼 보였다. 그래서 한곳에 모은다 — 다음에 만났을 때 같은 것임을 알아보려고.

## 네 상태는 다르다

| 상태 | 뜻 | 잘못 담기면 |
|---|---|---|
| **0** | 세었고 0이었다 | 없는 사실을 만든다 (0표를 얻었다) |
| **없다** | 세었고 해당이 없다 | 결손을 사실로 만든다 |
| **모른다** | 자료가 닿지 않는다 | 아는 것처럼 보인다 |
| **못 받았다** | 있는데 지금 못 가져왔다 | '없다'로 읽혀 사용자를 오도한다 |

'모른다'와 '못 받았다'는 겹쳐 보이지만 행동이 다르다. 앞은 **자료를 더 찾아야**
하고, 뒤는 **새로고침하면 된다**. 화면은 이 둘을 구별해 말해야 한다.

## 두 실패 모양은 같은 뿌리다

**① 한 필드가 두 질문에 답한다.** 필드 하나에 두 개념이 들어가면, 값 하나를 보고
어느 쪽인지 알 수 없다.

**② 입력이 비면 그럴듯한 기본값으로 조용히 떨어진다.** ①의 귀결이다. 두 뜻이
한 자리를 공유하니, 비었을 때 더 흔한 쪽으로 읽힌다 — 0, 오늘, 빈 배열, 최신 정당.

②가 위험한 건 **화면이 멀쩡해 보이기 때문**이다. 터지면 고친다. 그럴듯하면 남는다.

## 전량

`검사` 열은 그 판정을 지키는 자동 검사다. 사람이 읽는 note만 남기면 낡는다.

### 데이터 층

| 필드 | 겸하던 두 질문 | 가른 방법 | 검사 |
|---|---|---|---|
| `stream` | 조직 계보 ↔ 이념 위치 | `lineage_family` · `contemporary_position` | `tests/test_political_axes.py` |
| `relation` | 어떻게 생겼나 ↔ 어떻게 끝났나 | `formed_by` · `ended_by` | `tests/test_party_identity.py` |
| `ended_by` | 종료 ↔ 이름 복귀 | `temporary_rename` | `tests/test_party_identity.py` |
| `dissolved` | 소멸했다 ↔ 거기까지만 안다 | `dissolved_bound: last_known_active` | `tests/test_observed_parties.py` |
| `founded` | 시작했다 ↔ 거기서부터 안다 | `founded_bound: first_known_active` | `tests/test_observed_parties.py` |
| 이름 문자열 | 그 회차 정식명 ↔ registry 노드 | `official`(name_fidelity) · `resolved_to`(homonym 큐) | `tests/test_observed_parties.py` |
| `rank` | 득표 순 ↔ 의석 순 | `rank` · `seat_rank` | `check_rank_one_meaning` |
| `votes: 0` | 0표를 얻었다 ↔ 투표가 없었다 | `null` + `uncontested` | `check_uncontested_null` |

`dissolved_bound`가 전형적이다. 국민회는 1951년에 여당 지위를 잃었을 뿐 3·4대
총선에 계속 나왔고, 실제 소멸 시점은 자료가 없다. `dissolved`를 지우면 '현존'이
되어 뒤 시대 동명 정당을 삼키고, 날짜를 지어내면 없는 사실을 만든다. 경계는
유지하되 그 값이 **마지막으로 확인된 활동 시점**임을 표시한다.

무투표는 반대쪽 전형이다. 같은 사실이 한 파일 안에서 두 가지로 적혀 있었다 —
후보 1,038명 중 `votes: 0`이 691명, `null`이 347명. 0은 '0표를 얻었다'는 거짓
진술이고 null이 참이다. 같은 레코드의 `pct`는 이미 null이었다.

### 산출 층

| 자리 | 겸하던 두 질문 | 가른 방법 | 검사 |
|---|---|---|---|
| sitemap `lastmod` | 실제 갱신일 ↔ 오늘 | `data/sitemap_lastmod.json` (내용 해시) | `tests/test_sitemap.py` |
| `ran_in` | 출마했다 ↔ 득표 기록이 있다 | `votes is None`도 출마로 센다 | `tests/test_aggregation_gate.py` |
| `json.load` 실패 | 그 회차가 없다 ↔ 파일을 못 읽었다 | 전량 파싱 확인으로 휴면 고정 | `check_data_json_parses` |

sitemap은 CI에서만 틀렸다. shallow clone이라 git 날짜가 없고, 없으면 오늘로
떨어졌다 — 5,005개 페이지가 매일 '오늘 갱신됨'이 됐다. 로컬에선 안 보인다.

### 화면 층

| 자리 | 겸하던 두 질문 | 가른 방법 | 검사 |
|---|---|---|---|
| `pct` 표기 | 값 ↔ 무투표 ↔ 자료 없음 | `fmtPct(v, {uncontested})` · `—` | `check_missing_not_zero` |
| `roster_scope` null | 당선인 ↔ 모른다 | null이면 라벨을 안 붙인다 | `check_roster_scope` |
| `getJson` 폴백 | 정상적으로 비었다 ↔ 못 받았다 | `_loadFailed` · `dataLoadFailed()` | UI 불변식 (오프라인) |
| `#loading` 오버레이 | 불러오는 중 ↔ 실패해서 안 온다 | `failLoading()` | UI 불변식 (오프라인) |
| HTTP 404 | 원래 없다 ↔ 못 받았다 | `getJson` ↔ `getJsonOptional` | UI 불변식 (헛경보) |

마지막 셋은 서로 물려 있다. `getJson`이 실패를 표시하지 않으면 화면은 "조사가
없습니다"라고 **단언**한다. 반대로 404까지 실패로 세면 멀쩡한 화면에 경보가 뜬다 —
2대 대선엔 성연령 자료가 원래 없다. **'못 받음' 고지도 틀리면 똑같이 거짓말이다.**

## 새 필드를 만들기 전에

1. **이 필드가 몇 개의 질문에 답하는가.** 둘이면 지금 가른다. 나중에 가르는 건
   이미 쌓인 값을 되짚는 일이 된다.
2. **비었을 때 무엇으로 읽히는가.** 그 기본값이 사실인가, 그냥 그럴듯한가.
3. **틀렸을 때 터지는가, 그럴듯해 보이는가.** 뒤라면 검사가 필요하다.
4. **판정을 검사로 만들 수 있는가.** note만 남기면 낡는다. 못 만들겠으면 왜
   못 만드는지를 적는다.
5. **실제 케이스가 요구했는가.** 요구하지 않은 필드는 만들지 않는다.

## 검사는 변이로 검증한다

검사를 추가하면 **일부러 깨뜨려 잡히는지** 본다. 이 저장소에서 검사가 두 번
헛통과했다 — 한 번은 이웃의 가드가 빠진 가드를 가렸고, 한 번은 데이터가 0개라
자동 통과했다. 잡히지 않는 검사는 없는 것보다 나쁘다. 있다고 착각하게 한다.

오프라인 UI 검사에는 **양쪽 방향**이 다 있다.

    정상인데 실패 고지 없음      헛경보 금지
    못 받았다고 화면에서 말한다   침묵 금지

침묵 금지가 필요했던 이유가 있다. '거짓말 안 함'만 검사하면 아무 말도 안 하는
화면이 공짜로 통과한다 — archive 6개가 그렇게 통과하고 있었다.
