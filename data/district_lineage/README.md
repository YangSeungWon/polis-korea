# 총선 선거구 계보 (district lineage)

**두 회차를 비교해도 되는 단위와 안 되는 단위를 데이터로 판정한다.** 이것이 이
프로젝트의 완료조건이고, 화면은 아니다. 판정이 서기 전에는 총선 swing·득표율 delta를
만들지 않는다 — 경계가 바뀐 단위를 이어 붙이면 없던 변화가 만들어진다.

생성: `python3 scripts/normalize/build_district_lineage.py --all`
검증: `python3 tests/test_district_lineage.py`

## 왜 폴리곤인가

원래 계획은 `읍·면·동 → 회차별 선거구 membership`이었는데, **동 경계 시계열이 오래된
병목**이다. 그런데 우리에겐 이미 1~22대 선거구 폴리곤(`data/geo/district_{n}_geojson.json`)이
있고, 교차 면적이면 같은 질문에 답할 수 있다: *이 선거구는 지난 회차의 무엇이었고,
얼마나 같은가.*

부수 효과로 **이름으로는 절대 못 잡는 것**도 잡힌다. 2024년 군위군이 경북에서 대구로
편입돼 `대구 동구군위군을`이 된 것은 시도 경계를 넘는 변화라 문자열 비교로는 안 보인다.

## 관계 유형

| 관계 | 뜻 | comparable |
|---|---|---|
| `exact` | 1:1 · 양방향 ≥97% · 이름도 같다 | `yes` |
| `renamed` | 1:1 · 양방향 ≥97% · 이름만 다르다 | `yes` |
| `minor_boundary_change` | 양방향 90~97% | **`unknown`** |
| `boundary_changed` | 같은 자리지만 경계가 움직였다 | `no` |
| `split` | 이전 1 → 현재 N | `no` |
| `merged` | 이전 N → 현재 1 | `no` |
| `new` | 대응하는 이전 선거구가 없다 | `no` |
| `unresolvable` | 겹침이 흩어져 어느 쪽으로도 못 정한다 | `no` |

## `unknown`이 왜 필요한가 — 그리고 언제 필요 없는가

겹침 90~97% 구간은 **실제 경계 변화**일 수도 **폴리곤 정밀도 차이**일 수도 있다.
한쪽으로 밀면 둘 다 틀린다. `exact`로 밀면 실제 획정 변화를 놓치고,
`boundary_changed`로 밀면 멀쩡한 단위를 비교 불가로 버린다.

**다만 두 폴리곤의 출처가 같으면 정밀도로 설명할 수 없다.** 그때는 실제 변화다.
출처는 파일 자체에서 읽는다(추정하지 않는다) — `source_profile()`:

| 회차 | 지문 | 성격 |
|---|---|---|
| 1~8 | 소수 9자리 · `approx` 속성 | 근사(스스로 밝힘) |
| 9~20 | 소수 4자리 · LICENSE 없음 | 재구성 |
| 21·22 | 소수 4자리 · LICENSE 있음 | 오마이뉴스 원본 |

처음엔 이 구분 없이 90~97%를 전부 `unknown`으로 뒀는데, 22↔21은 **같은 출처**라
정밀도 차이로 설명할 수 없었다. 19건이 근거 없이 보류되고 있었던 것이다.

## 판정 보류 감사 (2026-08-05)

전체 21쌍 중 보류 141건이 **출처가 다른 3쌍에만** 몰려 있다:

| 쌍 | 보류 | 원인 |
|---|---|---|
| 21↔20 | 125 | 20대는 재구성(781KB), 21대는 원본(1.5MB) |
| 6↔5 | 12 | 5대는 소수 9자리 근사, 6대는 다른 계열 |
| 2↔1 | 4 | 1대에 `approx` 속성 없음 |
| 나머지 18쌍 | 0 | 출처 지문이 같다 |

**감축 경로**: 20대 폴리곤을 오마이뉴스 계열로 교체하거나 21대를 재구성 계열로
맞추면 125건이 판정된다. 읍·면·동 membership까지 갈 필요는 없다.
이건 `unknown`을 줄이는 것 자체가 목적이 아니라 **과거 총선에서 직접 delta를
계산할 수 있는 단위를 늘리는 것**이다.

그 전까지 총선 비교는 `comparable == "yes"`인 단위로만 만든다.
