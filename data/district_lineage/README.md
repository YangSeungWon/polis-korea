# 총선 선거구 계보 (district lineage)

**두 회차를 비교해도 되는 단위와 안 되는 단위를 데이터로 판정한다.** 이것이 이
프로젝트의 완료조건이고, 화면은 아니다. 판정이 서기 전에는 총선 swing·득표율 delta를
만들지 않는다 — 경계가 바뀐 단위를 이어 붙이면 없던 변화가 만들어진다.

생성: `python3 scripts/normalize/build_district_lineage.py --all`
검증: `python3 tests/test_district_lineage.py`

## 왜 폴리곤인가

원래 계획은 `읍·면·동 → 회차별 선거구 membership`이었는데, **동 경계 시계열이 오래된
병목**이다. 그런데 우리에겐 이미 1~22대 선거구 폴리곤(`data/geo/district_{n}_geojson.json`)이
있고, 교차 면적이면 같은 질문에 답할 수 있다: *이 선거구는 지난 회차의 무엇이었고,
얼마나 같은가.*

부수 효과로 **이름으로는 절대 못 잡는 것**도 잡힌다. 2024년 군위군이 경북에서 대구로
편입돼 `대구 동구군위군을`이 된 것은 시도 경계를 넘는 변화라 문자열 비교로는 안 보인다.

## 관계 유형

| 관계 | 뜻 | comparable |
|---|---|---|
| `exact` | 1:1 · 양방향 ≥97% · 이름도 같다 | `yes` |
| `renamed` | 1:1 · 양방향 ≥97% · 이름만 다르다 | `yes` |
| `minor_boundary_change` | 양방향 90~97% | **`unknown`** |
| `boundary_changed` | 같은 자리지만 경계가 움직였다 | `no` |
| `split` | 이전 1 → 현재 N | `no` |
| `merged` | 이전 N → 현재 1 | `no` |
| `new` | 대응하는 이전 선거구가 없다 | `no` |
| `unresolvable` | 겹침이 흩어져 어느 쪽으로도 못 정한다 | `no` |

## `unknown`이 왜 필요한가 — 그리고 언제 필요 없는가

겹침 90~97% 구간은 **실제 경계 변화**일 수도 **폴리곤 정밀도 차이**일 수도 있다.
한쪽으로 밀면 둘 다 틀린다. `exact`로 밀면 실제 획정 변화를 놓치고,
`boundary_changed`로 밀면 멀쩡한 단위를 비교 불가로 버린다.

**다만 두 폴리곤의 출처가 같으면 정밀도로 설명할 수 없다.** 그때는 실제 변화다.
출처는 파일 자체에서 읽는다(추정하지 않는다) — `source_profile()`:

| 회차 | 지문 | 성격 |
|---|---|---|
| 1~8 | 소수 9자리 · `approx` 속성 | 근사(스스로 밝힘) |
| 9~20 | 소수 4자리 · LICENSE 없음 | 재구성 |
| 21·22 | 소수 4자리 · LICENSE 있음 | 오마이뉴스 원본 |

처음엔 이 구분 없이 90~97%를 전부 `unknown`으로 뒀는데, 22↔21은 **같은 출처**라
정밀도 차이로 설명할 수 없었다. 19건이 근거 없이 보류되고 있었던 것이다.

## 판정 보류 감사 (2026-08-05)

전체 21쌍 중 보류 141건이 **출처가 다른 3쌍에만** 몰려 있다:

| 쌍 | 보류 | 원인 |
|---|---|---|
| 21↔20 | 125 | 20대는 재구성(781KB), 21대는 원본(1.5MB) |
| 6↔5 | 12 | 5대는 소수 9자리 근사, 6대는 다른 계열 |
| 2↔1 | 4 | 1대에 `approx` 속성 없음 |
| 나머지 18쌍 | 0 | 출처 지문이 같다 |

### 해결됨 (2026-08-05) — 원인은 외부 데이터가 아니라 우리 빌드 설정이었다

20대 원본 폴리곤을 찾으러 나섰는데, 답은 **우리가 이미 만들 수 있었다**는 것이었다.

`build_district_geojson.py`의 회차 설정을 보니 9~19·21·22대는 전부 `mode="nec_emd"`
(NEC 읍면동 매핑 + SGIS 동 경계 dissolve)인데 **20대만 `mode="wwolf"`** 였다.
혼자 다른 파이프라인이라 폴리곤이 어긋났던 것이다.

`fetch_district_emd.py 20`으로 NEC 읍면동 매핑을 받아(선거구 252개) 같은 방식으로
재생성했다:

| | 이전(wwolf) | 지금(nec_emd) |
|---|---|---|
| 파일 크기 | 781KB | **1486KB** (21·22대와 같은 규모) |
| 21대와 겹침 중앙값 | 93.9% | **99.6%** |
| 21↔20 비교 가능 | 54 | **204** / 253 |
| 21↔20 판정 보류 | 125 | **18** |
| 전체 판정 보류 | 141 | **34** |

집계 게이트도 크게 개선됐다 — 수도권 편차 −29.3%p → **+1.7%p**, 1위 정당 구성
편차는 기준 안으로 들어왔다. 다만 선거인 coverage 80.6%로 여전히 차단된다.
그래도 아쉽지 않다 — 전국 지표는 `build_general_national.py`가 매칭 없이 내기 때문이다.

**교훈**: "출처가 다르다"는 감사 결론은 맞았는데, 원인을 외부에서 찾았다.
같은 저장소 안에서 한 회차만 다른 파이프라인을 쓰고 있었다.

### 21↔20 source harmonization 감사 (2026-08-05, 위 수정 이전)

폴리곤을 새로 구하기 전에 차이를 수치로 분해했다 —
`python3 scripts/audit/audit_geometry_sources.py --pair 21 20`

| 항목 | 결과 | 뜻 |
|---|---|---|
| 계통 offset | 22m | 측지계 차이 **아님** |
| vertex/선거구 | 158 → 317 (2.0배) | 단순화 수준이 다르다 |
| 총면적 | +1.31% | 21대가 더 정밀 |
| 같은 tolerance 단순화 | 90~97% 구간 119 → 106 (555m에서도) | **표현으로 설명 안 됨** |
| 양방향 비대칭 | 0.4%p | 한쪽 단순화가 아니라 **서로 다른 경계** |
| overlap<90% 분포 | 서울 21·경기 14·부산 7 | 도시 집중 = 실제 인구 재획정 패턴 |

**결론: 21↔20의 차이는 대부분 실제 2020년 획정 조정이다.** 단순화·snap 같은
표현 정규화로는 줄지 않으므로 적용하지 않았다(적용하면 정보만 버린다).

다만 20대는 재구성본이라 그 자체의 부정확성을 검증할 근거가 없다. 그래서 125건은
`unknown`으로 남긴다 — '실제 변화일 가능성이 높다'와 '실제 변화다'는 다르다.

**남은 감축 경로**: 20대 원본 폴리곤(오마이뉴스 계열) 확보. 그것이 안 되면
읍·면·동 membership. **목표는 125건을 전부 `yes`로 만드는 것이 아니다** —
출처 차이가 제거된 뒤 실제 경계 변경이면 `no`가 정상이다.

### unknown 감축과 별개인 것

같은 출처인데도 비교 가능이 낮은 쌍이 있다(9↔8: 1, 13↔12: 4, 20↔19: 30).
여기서 시스템은 `unknown`이 아니라 **"경계가 실제로 달라 직접 비교 불가"라고
자신 있게 판단한 상태**다. split/merge 재집계라는 별도 과제이며,
이번 source harmonization의 대상이 아니다.

> `unknown`을 줄이는 작업 ≠ `no`를 `yes`로 만드는 작업

그 전까지 총선 비교는 `comparable == "yes"`인 단위로만 만든다.
